# Foundation: Decisions

Sub-project 1. This sets up the base that every later feature builds on.

## Context: what the initial scaffold (`d3cbea6`) already had

- Django 5.2 + DRF 3.18 + psycopg2 + python-dotenv, installed in `backend/venv/` (Python 3.10.3 via pyenv)
- `settings.py` generated by `django-admin startproject`, unchanged

**Problems found in the scaffold:**

- The database is still **SQLite**, not Postgres.
- `.env` is never loaded. `python-dotenv` is installed but not used.
- `SECRET_KEY` is **written directly in the code and committed to git**. It has to move to `.env`, and a new key has to be generated, because the committed one should be treated as leaked.
- DRF isn't in `INSTALLED_APPS`.
- There's no custom User model. Django strongly recommends creating one **before the first migration**, because switching later is painful.

Local Postgres: PostgreSQL 17 (DBngin) on `localhost:5432`.

## Decisions

### Package management: venv + pip + `requirements.txt`
- **Why:** It's the standard baseline that's built into Python and assumed by the Django docs. It's the best place to learn from, because tools like uv and Poetry automate these same steps.
- **Revisit:** Switching to `uv` later is cheap. We'll probably add Docker when we deploy.

### User model: email only, no username, no passwords for end users
- `email` is the unique login identifier, and there's **no `username` field**.
- End users get an **unusable password**, because auth is passwordless (see [accounts/auth.md](../accounts/auth.md)). Only staff/admin accounts have a password, for logging into Django admin.
- The User model holds **authentication data only**. Onboarding answers, goals, the trial and so on go in separate related models.
- **Why:** This follows the simplicity principle, and it matches mobile-first passwordless auth. Keeping User lean means profile data can change without affecting login.

### Scope of the foundation sub-project
1. Settings come from `.env` (`SECRET_KEY`, `DEBUG`, `DATABASE_URL`, `ALLOWED_HOSTS`).
2. Postgres replaces SQLite.
3. Custom User model, created before the first migration.
4. DRF registered with defaults: JSON only, authenticated users only by default.
5. Tests run with `pytest`.
6. Linting and formatting with `ruff`.
7. `GET /api/health/` endpoint with a test, proving the request → view → response path works end to end.

### Python 3.13 + Django 5.2 LTS
- Rebuild `backend/venv` on Python 3.13 (installed with `pyenv install 3.13`). Keep Django on the 5.2 LTS line.
- **Why:** Python 3.10 reaches end of life in October 2026, so it gets no more security fixes. 3.13 is mature and every library supports it. Django 5.2 LTS gets security fixes until April 2028, which is the right base for a product we're launching.
- **Rejected:** Python 3.14 + Django 6.x (shorter support windows, so more frequent upgrades). Staying on 3.10 (EOL).

### Configuration: one `settings.py` driven by environment variables
- `SECRET_KEY` (required, newly generated), `DEBUG` (defaults to `False`), `ALLOWED_HOSTS`, `DATABASE_URL`, loaded from `backend/.env` via `python-dotenv`. `.env.example` is updated to match.
- **Why:** One file, with no base/dev/prod drift. Same model as Laravel's `.env`. Simplest option.
- **Rejected:** split `settings/base.py`, `dev.py`, `prod.py` (three files to keep in sync).

### Database: local Postgres, new `mealcycle` database
- Use the existing local PostgreSQL 17 (DBngin) on `localhost:5432`, with a new database called `mealcycle`. The user approved creating it and running migrations on it (2026-10-17). The other databases on that server (`kespas`, `kespas_testing`) belong to another project and must not be touched.
- `dj-database-url` parses `DATABASE_URL`. SQLite is removed, and tests also run on Postgres (pytest-django creates a temporary `test_mealcycle` database).
- Driver: `psycopg` (v3) replaces `psycopg2-binary`.
- Terminology: in Postgres, a *database* holds *schemas* (namespaces, default `public`), and schemas hold tables. Django puts everything in the `public` schema of the database we point it at.

### Dependencies: `requirements.txt` + `requirements-dev.txt`
- Prod: Django 5.2, DRF, psycopg, python-dotenv, dj-database-url.
- Dev: `-r requirements.txt` plus pytest, pytest-django, ruff (≈ Composer's `require-dev`).
